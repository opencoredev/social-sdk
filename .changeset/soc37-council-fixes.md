YouTube resource writes (playlists, playlist items, subscriptions, channel sections, live broadcasts and streams, live chat messages, moderators and bans, captions, playlist images, comment threads, comment replies, Analytics groups and group items, and Reporting jobs) now reject a success response without a non-empty string `id` with `ambiguous_outcome` and `reconcile-first`; `native.playlists` writes and reads the `localizations` part (with `snippet.defaultLanguage` required) and accepts `parts` for lists; and LinkedIn `comments.reply` reports `ambiguous_outcome` instead of `upstream_failure` when the sent reply's response is not an object or lacks a valid comment URN.

Buffer mutations that time out, are cancelled, or lose their answer after dispatch now report `ambiguous_outcome` with `reconcile-first`, Buffer errors no longer copy Buffer's message text (only recognized GraphQL codes and payload error types such as `UnauthorizedError` survive), and YouTube `liveBroadcasts` bind and transition, live chat poll closure, video, channel and comment updates, ad cuepoints, thumbnail sets, and abuse reports now require the written resource (its `id`, the bound stream, or the transitioned lifecycle state) before resolving, otherwise `ambiguous_outcome` with `reconcile-first`.

YouTube and LinkedIn writes now resolve only on their documented success answer: deletes, ratings, moderation, watermarks and other no-content writes need the documented status (204 on YouTube; 204, 202 or 200 per LinkedIn endpoint), updates must return the addressed ID, a 200 JSON `null` no longer counts as an Analytics group item that was already present, a malformed `contentDetails` no longer confirms a broadcast unbind, and LinkedIn poll, reshare, event-post, reaction, comment and event creates need a valid URN or ID, so any other answer after the request was sent is `ambiguous_outcome` with `reconcile-first`.
