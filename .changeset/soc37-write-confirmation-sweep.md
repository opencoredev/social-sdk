Writes are confirmed only by the provider's documented success answer, and errors keep provider text out.

- Every adapter (direct platforms, managed backends, the shared post lifecycle and TikTok token revocation) resolves a sent write only on the provider's documented success answer. Any other answer after the request was sent, such as `null`, an array, or a missing or wrong-type field, now throws `ambiguous_outcome` with `retryDisposition: { kind: "reconcile-first" }` instead of a definite failure. Normalized `posts.publish` does not throw for these: it returns an `unknown` outcome, so check `result.outcomes` even when the call resolves. Definite provider rejections and checks made before sending keep their specific error codes; a 5xx answer after a write was sent, or a failed Facebook or Instagram raw read-back, can also be `ambiguous_outcome`. `revokeTikTokOAuthToken` returns `"revoked"` only for TikTok's empty success body (or `{}`).
- Errors map provider failures to recognized machine codes and fixed SDK messages instead of copying provider prose, and an unknown Zernio error category becomes `upstream_failure`. A few errors keep a validated provider value, such as YouTube's upload error reason or a LinkedIn document ID.
- Zernio and Post for Me delivery outcomes report a missing backend status as `unknown` and any other status that is not a plain token as `unrecognized`, and keep a published link only when it is an HTTPS URL with no username or password. Buffer delivery outcomes return a post's string status and, on a published post, its `externalLink` as received. PostFast delivery outcomes return a post's string status as received, except that an approval-pending scheduled post reports `SCHEDULED/PENDING_APPROVAL`. For both, a missing or non-string status becomes `unknown`.
- Newly documented as not supported, each with a raw-request route: Buffer `editPost` `assets` and `metadata` fields (text, `at`, `saveToDraft`, `tagIds`, `approvalChange`, `aiAssisted` and `draftId` are supported), and creating or deleting Buffer tags; Postiz delete by group; X edits other than text; Bluesky starter pack edits and `chat.bsky.moderation.updateActorAccess`; Facebook Page Post update fields beyond the message, pin, hide, AI label and schedule, photo and video edits, and album creation; removing Instagram product tags; undoing a Threads repost; and the Zernio routes outside posting (inbox edits and reactions, pinning published posts, queue slot management, direct or prepared media uploads, API key management, connected-app revocation, and its non-social products; OAuth apps are managed with `createOAuthApp`, `updateOAuthApp` and `deleteOAuthApp`).
- Facebook `native.updatePost` accepts `scheduleAt`, sent as `scheduled_publish_time`, to reschedule a scheduled Page post.
