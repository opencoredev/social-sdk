[Zernio](https://zernio.com) is an optional managed backend. Create an account and pick a plan on [zernio.com](https://zernio.com), then create an API key in its dashboard. The key stays on the server and is passed to the adapter; connected accounts are provider records that your application must map to tenants.

```ts
import { readFile } from "node:fs/promises";
import {
  createSocial,
  connectedAccountRef,
  platformPostRef,
  type AdapterOperationContext,
  type BackendPostRef,
  type ConnectedAccountRef,
  type ConversationRef,
  type DeliveryOutcome,
  type Platform,
} from "@opencoredev/social-sdk";
import { zernio } from "@opencoredev/social-sdk/cloud/zernio";

// Get tenantId from your authenticated server session and enforce account grants.
const authorization = { tenantId: "tenant-from-session" };
const social = createSocial({
  backend: zernio({
    apiKey: process.env.ZERNIO_API_KEY!,
    webhookSecret: process.env.ZERNIO_WEBHOOK_SECRET!,
  }),
});
const accounts = await social.accounts.list({ backend: "default", authorization });

function selectAccount<P extends Platform>(platform: P): ConnectedAccountRef<P> {
  const match = accounts.items.find((item) => item.ref.platform === platform);
  if (!match) throw new Error(`Connect a ${platform} account first.`);
  return connectedAccountRef({
    backend: match.ref.backend,
    platform,
    accountId: match.ref.accountId,
  });
}

const account = selectAccount("x");
const youtubeAccount = selectAccount("youtube");
const instagramAccount = selectAccount("instagram");
const at = new Date(Date.now() + 7 * 86_400_000).toISOString();
const video = new Blob([await readFile("./assets/release-walkthrough.mp4")]);
```

The adapter supports account listing, publishing, external platform-feed reads and delivery status, media upload, post and account analytics, verified webhooks, recent X search, comments for X, Threads, Bluesky, YouTube, Instagram, LinkedIn, Facebook Pages, Reddit and TikTok Business accounts, and messaging for X, Bluesky, Instagram, Facebook Pages, Reddit and Telegram. Provider permissions and recipient or reply-window rules still apply.

:::warning
Reddit is unavailable through Zernio. Zernio's [platform comparison](https://docs.zernio.com/platforms/compare), checked November 4, 2026, says Reddit is temporarily unavailable: Reddit has blocked third-party apps from its API, so Zernio cannot post to Reddit, read Reddit messages, or sync Reddit analytics. Zernio says Reddit Ads is not affected. The SDK's Reddit publishing, messaging, and analytics methods remain in place, but Zernio refuses those requests until it restores Reddit. The Reddit sections on this page describe the integration for when it returns.
:::

Verify `X-Zernio-Signature` over the raw request bytes before decoding; accept events into a durable, tenant-resolved inbox. See [events](/events) and [capabilities](/reference/capabilities).

Run the setup on your server with your own assets and connected accounts. The later examples reuse its typed accounts, future `at`, and `authorization`. In a multi-tenant app, configure an [authorization policy](/concepts/tenant-authorization) backed by your account grants; a tenant ID alone does not enforce access. Related server helpers are in `examples/snippets/backend-zernio.ts`.

`posts.list` requests `source=external`: it reads synced platform posts and excludes posts created through Zernio. Use the stored `delivery` with `getDelivery` for backend publication status.

Zernio post creation sends the derived target retry key as `Idempotency-Key`, including when a retry uploads media to a different URL. This provider replay key does not bypass completed claims in a configured client idempotency store.

## Native calls

Zernio's routes beyond the normalized client, such as connections, profiles, drafts and approval, analytics reports, inbox management, Google Business, Reddit, Discord and webhook settings, come from a separate import, so an app that only publishes does not bundle them:

```ts
import { zernioNative } from "@opencoredev/social-sdk/cloud/zernio-native";

const native = zernioNative({ apiKey: process.env.ZERNIO_API_KEY! });
```

`zernioNative` takes the same options as `zernio` and sends the same requests. Pass the same options object to both, as in `const options = { apiKey }; zernio(options); zernioNative(options);`, so they share one default media store and a media ref uploaded through `zernio(options).media.upload` can be used in native submissions. With separate options objects, configure a shared `mediaStore`. Each method takes an `AdapterOperationContext` and checks the account against its `backendInstance`, but skips the client's authorization policy and concurrency checks, so run your own tenant checks first. The sections below call it `native`.

## Publish a video

For TikTok photo posts, Zernio maps `options.title` to the post title (up to 90 UTF-16 code units), `options.description` to the long-form caption (up to 4,000), and sends `mediaType: "photo"` when `options.mediaType` is set to `"photo"`. Set `autoAddMusic: true` to request automatic music; these options are photo-only and are rejected for TikTok video posts. Video posts continue to send `autoAddMusic: false` by default.

Pass the file as a `Blob` with its MIME type and filename; the adapter uploads it to Zernio before it creates the post. Each target takes its platform's options, and images also accept `altText`.

```ts
const result = await social.posts.publish(
  {
    targets: [
      {
        account: youtubeAccount,
        options: { title: "Release walkthrough", visibility: "unlisted", madeForKids: false },
      },
      { account: instagramAccount, options: { shareToFeed: true } },
    ],
    content: {
      text: "A two-minute tour of the new release.",
      media: [
        {
          kind: "video",
          source: { kind: "blob", blob: video, fingerprint: "release-walkthrough-v1" },
          mimeType: "video/mp4",
          filename: "release-walkthrough.mp4",
        },
      ],
    },
    idempotencyKey: "release-walkthrough-v1",
  },
  { authorization: { tenantId: "tenant-from-session" } },
);
```

`result.outcomes` has one entry per target. Type each account as `ConnectedAccountRef<"youtube">` and so on so TypeScript checks the options. The adapter rejects LinkedIn `visibility: "connections"` and Threads `replyControl` at preparation. An X target with a `platform-post` `replyTo` is published as a reply through `platformSpecificData.replyToTweetId`, so `publishSequence` with `replyToPrevious` builds X threads. Other platforms reject publish-time replies with `reply.use_comments`.

Instagram Reels have two unrelated audio options. `audioConfiguration` adds a licensed music track or original sound from Instagram's audio catalog: find its `audioId` with `searchInstagramAudio`, then set `audioVolume` for the track and `videoVolume` for the video's own sound (both default to 100; `videoVolume: 0` silences the original sound under the track). It needs an Instagram account connected through Facebook Login, and Zernio fails the post rather than publishing without the track if the track is unavailable at publish time. `audioName` adds no music: it only renames the Reel's original audio from "Original Audio", and Instagram lets you set that name once. `muteAudio: true` makes Zernio remove the audio track from the file itself, so the published video is silent for good and the sound cannot be restored on Instagram. ### Media options and recycling

Every platform also takes `mediaOptions`, one object per attachment in media order (`{}` for an attachment with no options). Zernio maps `subtitles` on a video: 1 to 20 SRT or WebVTT tracks, each `{ url, language }` with a public HTTPS `url` that serves the file without a redirect and a BCP-47 `language` such as `en` or `pt-BR`, each language once. They go to `mediaItems[].subtitles`; Zernio downloads and converts them and sends every track to YouTube and Facebook videos, every track up to 20 KB to Bluesky, the first track to X and the first English track to LinkedIn, and skips the rest with a warning. A media item's `thumbnail` (a public HTTPS URL) becomes the video's custom `thumbnail` on Facebook, YouTube and LinkedIn, and `instagramThumbnail`, the Reel cover, on Instagram. Other platforms reject a thumbnail with `media.thumbnail`.

`recycling` reposts a post on a fixed gap, which Zernio calls evergreen recycling. Give `gap` (an integer of at least 1) and `gapFreq` (`week` or `month`, Zernio's default), and optionally `startDate` (ISO 8601; defaults to the scheduled time), `expireCount` (stop after that many copies), `expireDate` and `contentVariations` (2 to 20 texts used in turn for the copies, which Zernio recommends for X and Pinterest to avoid duplicate-content flags). The adapter sends it as the request's `recycling` with `enabled: true`. Zernio excludes YouTube and TikTok from recycling, so `recycling` on those targets fails preparation with `recycling.platform`.

```ts
await social.posts.publish({
  targets: [
    {
      account: youtubeAccount,
      options: {
        title: "Launch walkthrough",
        visibility: "public",
        madeForKids: false,
        notifySubscribers: false,
        mediaOptions: [{ subtitles: [{ url: "https://cdn.example.com/en.srt", language: "en" }] }],
      },
    },
    { account: xAccount, options: { recycling: { gap: 2, gapFreq: "week", expireCount: 6 } } },
  ],
  content: { text: "Launch walkthrough", media: [video] },
});
```

A poll cannot carry media, so the X target above shares only the text; split targets into separate calls when their media differs.

### Threads with `threadItems`

On X, Threads and Bluesky, `options.threadItems` lists the posts after the first. The adapter sends the target's own `text` and media as `threadItems[0]` and these items after it, in one Zernio request, so the whole thread is one backend record and one delivery. Each item has `text`, public HTTPS `media` (`kind`, `url`, optional `altText`), or both. Use `publishSequence` instead when each post needs its own uploaded media or its own outcome.

```ts
await social.posts.publish(
  {
    targets: [
      { account, options: { threadItems: [{ text: "2/ Auth" }, { text: "3/ Versioning" }] } },
    ],
    content: { text: "1/ What makes a good API" },
  },
  { authorization },
);
```

## Schedule and check a delivery

Set `schedule.at`, with an optional IANA `timeZone`, and store the outcome's `delivery` reference. Later, read it with `getDelivery` and handle every state instead of treating the result as a boolean.

```ts
const scheduled = await social.posts.publish(
  {
    targets: [{ account }],
    content: { text: "Office hours start at 10:00." },
    schedule: { at, timeZone: "Europe/Berlin" },
  },
  { authorization },
);
const delivery = scheduled.outcomes[0]?.delivery; // store with the publication

if (!delivery) throw new Error("No delivery was confirmed; reconcile the submission first.");

// Later, for example from a job:
const outcome = await social.posts.getDelivery(delivery, { authorization });
const action = nextStep(outcome);

function nextStep(outcome: DeliveryOutcome): string {
  switch (outcome.state) {
    case "published":
      return `published ${outcome.url ?? outcome.post.postId}`;
    case "scheduled":
      return `scheduled as ${outcome.job.jobId}; check again after the scheduled time`;
    case "accepted":
    case "processing":
      return "Zernio is still working; check again later";
    case "failed":
      return outcome.retryDisposition.kind === "after-reconnect"
        ? "ask the account owner to reconnect, then publish again"
        : `failed with ${outcome.code}`;
    case "cancelled":
      return "cancelled";
    case "not-submitted":
      return `not submitted: ${outcome.reason}`;
    case "unknown":
      return "state is unclear; reconcile before retrying";
  }
}
```

## Cancel or remove a post

Cancelling works on a record with one destination whose time is still in the future. Zernio deletes the record, so the result reports `backendRecord: "deleted"`.

```ts
if (outcome.state === "scheduled") {
  const { backendRecord } = await social.posts.cancelScheduled(outcome.job, { authorization });
}
```

To take down a post that already published, pass the `post` from a `published` outcome to `removeFromPlatform`. Zernio unpublishes from X, Threads, Bluesky, YouTube, LinkedIn, Facebook Pages, Pinterest, Reddit, Discord, Telegram and Google Business Profile through `POST /v1/posts/{id}/unpublish`; it cannot delete Instagram, TikTok or Snapchat posts, so those are not declared. The `post` carries the Zernio record ID that removal needs; personal Facebook profiles are not supported.

```ts
if (outcome.state === "published") {
  await social.posts.removeFromPlatform(outcome.post, { authorization });
}
```

`deleteBackendRecord` deletes a Zernio record whose status is `draft`, `failed` or `cancelled`, the statuses where nothing is live on a platform. It refuses scheduled, partial and published records: cancel a schedule with `cancelScheduled` and take a live post down with `removeFromPlatform`.

## Recover a duplicate create

A post-create HTTP 409 reports `idempotency_conflict`. When Zernio returns an existing post ID, `social.posts.publish` returns a failed outcome with an account-scoped `delivery` reference and `retryDisposition: { kind: "reconcile-first" }`. Call `social.posts.getDelivery(outcome.delivery)` before deciding whether to submit again. The status read checks for a matching destination and does not infer success from the duplicate alone. Direct adapter errors without a recovery ID retain their retry guidance. The ID identifies a backend record, not a published platform post.

If the key is still processing and Zernio supplies `Retry-After`, the error instead reports `after-delay`. If no safe recovery ID or delay is available, reconcile manually in Zernio before deciding whether to submit again. The caller owns any later attempt with the same key; the transport never replays a write. Unrecognized or oversized bodies retain the generic status error without exposing provider text or media URLs.

## Read analytics

Post metrics include impressions, reach, likes, comments, shares, saves, clicks, views, follows, and reposts where Zernio reports them. Account metrics report followers when available; followers may be omitted without the analytics add-on. Missing counters are not zero.

```ts
if (outcome.state === "published") {
  const postMetrics = await social.analytics.getPostMetrics(outcome.post, { authorization });
}
const accountMetrics = await social.analytics.getAccountMetrics(account, { authorization });
```

`zernioNative` reads Zernio's deeper analytics. Each needs the Analytics add-on; without it Zernio answers `requiresAddon` and the adapter reports `billing_required`.

- `followerStats({ accounts, fromDate?, toDate?, granularity? })` reads follower count history and growth from `GET /v1/accounts/follower-stats`, keyed by account ID. Zernio refreshes follower counts once a day.
- `accountInsights({ account, kind?, metrics?, breakdown?, fromDate?, toDate? })` reads account insights (reach, views, accounts engaged, interactions) for Instagram, Facebook Pages, TikTok, YouTube channels and LinkedIn organizations, or audience demographics with `kind: "demographics"` (age, gender, country, city; Instagram needs at least 100 followers). Data can lag up to 48 hours.
- `youtubeDailyViews({ post, fromDate?, toDate? })` reads one video's daily views, watch time (`estimatedMinutesWatched`), average view duration and percentage, and subscriber changes from `daily-views`. YouTube finalizes these about three days late; `provisionalSince` marks the first provisional day. The channel must have granted the YouTube Analytics scope.
- `bestTimes({ account })` returns the best time to post as weekday and UTC hour slots with average engagement (`best-time`), and `contentDecay({ account })` shows how quickly posts reach their final engagement (`content-decay`).

### Post timelines, change feeds and platform reports

These also need the Analytics add-on.

- `postTimeline({ delivery, fromDate?, toDate? })` reads a post's daily series from `GET /v1/analytics/post-timeline`, one row per day and platform with impressions, reach, likes, comments, shares, saves, clicks, views and, where the platform reports them, completion rate, profile views and replays.
- `analyticsDelta({ accounts, cursor?, limit?, profileId? })` reads `GET /v1/analytics/delta`, the post snapshots that changed since a cursor. Store the returned `nextCursor` and pass it back to sync only what changed; `isDeleted` marks posts removed on the platform. Rows for accounts outside `accounts` are dropped.
- `analyticsDashboard({ fromDate, toDate, profileId?, platform?, comparePrevious?, topPosts?, recentPosts? })` returns totals, follower counts, a daily series and up to 25 top and recent posts for a date range in one call (`GET /v1/analytics/dashboard`), with the previous period when `comparePrevious` is set.
- `instagramFollowerHistory({ account, fromDate?, toDate?, metricType? })` reads `instagram/follower-history`, and `instagramOnlineFollowers({ account })` reads `instagram/online-followers`, the hours of each day when followers are online. `instagramStoryInsights({ account, storyId })` reads one story's metrics, marking whether they are `live` or `cached`.
- `facebookPostEarnings({ post, metrics? })` reads a Facebook post's monetization earnings (`facebook/post-earnings`); metrics the Page is not enrolled for come back in `unavailableMetrics` with a reason. `facebookPostReactions({ post })` returns the reaction breakdown (like, love, haha, wow, sad, angry, care).
- `linkedInPostAnalytics({ post })` reads one LinkedIn post's stats by URN from `linkedin-post-analytics`, `linkedInPostReactions({ post, limit?, cursor? })` lists who reacted, and `linkedInAggregateAnalytics({ account, aggregation?, fromDate?, toDate?, metrics? })` reads an account's aggregate stats as `TOTAL` or `DAILY`.
- `googleBusinessSearchKeywords({ account, startMonth?, endMonth?, pageToken? })` lists the search terms that showed a Google Business location, by month (`YYYY-MM`). Google hides exact counts below a threshold and returns `impressionsThreshold` instead.
- `googleBusinessPerformance({ account, metrics?, fromDate?, toDate? })` reads a Google Business location's daily metrics from `GET /v1/analytics/googlebusiness/performance`: Maps and Search impressions on desktop and mobile (`BUSINESS_IMPRESSIONS_DESKTOP_MAPS`, `BUSINESS_IMPRESSIONS_DESKTOP_SEARCH`, `BUSINESS_IMPRESSIONS_MOBILE_MAPS`, `BUSINESS_IMPRESSIONS_MOBILE_SEARCH`), `WEBSITE_CLICKS`, `CALL_CLICKS`, `BUSINESS_DIRECTION_REQUESTS`, `BUSINESS_CONVERSATIONS`, `BUSINESS_BOOKINGS`, `BUSINESS_FOOD_ORDERS` and `BUSINESS_FOOD_MENU_CLICKS`. Each returned metric has a `total` and one `{ date, value }` per day; metrics Zernio does not return are absent, not zero. Omit `metrics` for all of them. Dates are `YYYY-MM-DD`; Zernio defaults to the last 30 days, goes back at most 18 months, and its data can lag 2 to 3 days (`dataDelay`). These are location metrics; Google Business posts have no per-post metrics. The method sends `fromDate` and `toDate`, not Zernio's deprecated `startDate` and `endDate` aliases.

### Inbox analytics

`inboxAnalytics({ report, fromDate, toDate?, account?, profileId?, platform?, limit?, page? })` reads Zernio's messaging reports from `GET /v1/analytics/inbox/{report}`: `volume` (received, sent, read and failed messages with a daily series and per-platform split), `heatmap` (a day-of-week by hour grid), `source-breakdown`, `response-time` (median, p90 and p99 seconds to reply, with a histogram), `top-accounts` by volume, and `conversations` (counts per conversation). `conversationAnalytics({ conversation, fromDate, toDate? })` reads one conversation's counts and series. Dates are `YYYY-MM-DD`.

## Reply to comments

List comments on a published post, then reply with a comment reference built from the post and the comment `id`.

```ts
if (outcome.state !== "published") throw new Error("Wait for a confirmed platform post.");
const post = outcome.post;
const comments = await social.comments.list(post, { limit: 20, authorization });
const commentId = comments.items[0]?.["id"];

if (typeof commentId === "string") {
  await social.comments.reply(
    { ...post, kind: "comment", commentId },
    { text: "Thanks for watching." },
    { authorization },
  );
}
```

Comments on Reddit and TikTok Business accounts use the same calls. `zernioNative` adds the rest of Zernio's comment inbox:

- `listCommentReplies({ comment })` lists replies to one comment on Facebook, Instagram, Reddit and TikTok.
- `moderateComment({ comment, action })` hides or unhides a comment (`POST` or `DELETE .../{commentId}/hide`) on Facebook, Instagram, Threads, X and TikTok.
- `deleteComment({ comment })` deletes a comment on Facebook, Instagram, Threads, LinkedIn, Reddit, Bluesky, X, YouTube and TikTok. This is the `comments.delete` capability; it cannot be undone.
- `privateReply({ comment, text })` answers an Instagram or Facebook comment with a private DM. Meta allows one private reply per comment, within seven days of it.
- `likePost`, `unlikePost`, `likeComment` and `unlikeComment` like and unlike posts and comments on LinkedIn (with an optional `reactionType` such as `PRAISE`), X, Facebook, YouTube and Bluesky (pass the post `cid`, and keep the returned `likeUri` to unlike). `pinComment({ comment, pinned })` pins or unpins a comment on your own post.

- `editComment({ comment, text })` edits your own Reddit comment with `PATCH /v1/inbox/comments/{postId}/{commentId}`; Zernio edits Reddit comments only.

## Receive webhooks

Choose a strong HMAC secret, register it with the endpoint URL in Zernio webhook settings, and store the same value as `ZERNIO_WEBHOOK_SECRET` on your server. The setup passes it as `webhookSecret` to the adapter.

Read the raw bytes, verify the signature, then decode and accept the event. Only the verify call sits inside the `try`, so a decoding or inbox failure is not reported as an authentication error.

```ts
import { SocialError } from "@opencoredev/social-sdk";
import {
  acceptWebhook,
  decodeWebhook,
  verifyZernioWebhook,
  type EventInbox,
} from "@opencoredev/social-sdk/server";

export function webhookRoute(input: {
  endpointId: string;
  inbox: EventInbox;
  resolveTenants: (backend: string, accountIds: readonly string[]) => Promise<readonly string[]>;
}) {
  return async function POST(request: Request): Promise<Response> {
    const body = new Uint8Array(await request.arrayBuffer());

    try {
      await verifyZernioWebhook({
        secret: process.env.ZERNIO_WEBHOOK_SECRET!,
        headers: request.headers,
        body,
      });
    } catch (error) {
      if (error instanceof SocialError && error.code === "unauthorized")
        return new Response("unauthorized", { status: 401 });
      throw error;
    }

    const event = await decodeWebhook({ provider: "zernio", backend: "default", body });
    const accepted = await acceptWebhook({ event, ...input });
    return new Response(accepted.state, { status: 202 });
  };
}
```

`inbox` is your durable event store and `resolveTenants` maps Zernio account IDs to your tenants. See [events](/events) for both.

Decoded events keep Zernio's name in `originalType`. `post.cancelled`, `post.recycled`, `post.external.created` and `post.external.updated` decode as `publication.updated`; `message.sent`, `message.delivered`, `message.read`, `message.failed`, `message.edited` and `message.deleted` as `message.updated`; `reaction.received` as `reaction.received`; and `review.new`, `review.updated`, `review.deleted` and `review.restored` as `review.updated`. `account.permissions_changed` (an account on your own OAuth app hit a missing permission and stays connected for its other areas) and `account.rate_limited` (a mailbox entered a sending cooldown) decode as `account.updated`; `conversation.started` (the first message between an account and a contact) and `conversation.control_changed` (Meta handover moved who answers) as `conversation.updated`; `referral.received` as `message.referral`; `message.played` as `message.updated`; and `analytics.synced`, sent after each hourly analytics sync of an account, as `insights.updated`. `webhook.test` deliveries carry no account and decode as `unknown`, as do other events.

### Manage webhooks

`zernioNative` manages subscriptions on your API key through `/v1/webhooks/settings`, so they can be provisioned from code:

- `createWebhook({ name, url, secret?, events, isActive?, profileIds?, accountIds? })` subscribes an HTTPS endpoint to the listed events. Use the same `secret` as the adapter's `webhookSecret`.
- `listWebhooks()`, `updateWebhook({ webhookId, ...fields })` and `deleteWebhook({ webhookId })` read, change and remove subscriptions. Returned settings never include the secret.
- `testWebhook({ webhookId, event? })` sends a test delivery, optionally as a sample `post.failed` or other event marked `test: true`.

## Connect accounts

`zernioNative` lists your Zernio profiles and starts a hosted connection flow. Native calls skip the client's authorization and concurrency checks, so run them only after your own checks.

```ts
const context: AdapterOperationContext = {
  backendInstance: "default",
  correlationId: crypto.randomUUID(),
  retryBudget: { maxAttempts: 1, maxElapsedMs: 30_000 },
  authorization: { tenantId: "tenant-from-session" },
};

const redirectUrl = "https://app.example.com/zernio/callback";
const native = zernioNative({ apiKey: process.env.ZERNIO_API_KEY! });
const profiles = await native.listProfiles(context);
const profileId = profiles[0]?.["_id"];

if (typeof profileId === "string") {
  const { url } = await native.createConnection({ platform: "x", profileId, redirectUrl }, context);
}
```

A profile groups accounts; its `_id` is not a connected-account ID and cannot be used as a publish target. After the provider flow completes, list accounts again on the server, identify the newly connected account from the authorized connection session, and store its `ref.accountId`, backend and platform with that tenant's grant. Recheck the account identity before granting access. A redirect or returned URL is not tenant authorization.

`createConnection` also takes Zernio's connect options:

- `reconnectAccountId` refreshes an existing account of the same platform and profile instead of adding a new one, which is how an expired connection is repaired. Add `expectedPlatformUserId` or `expectedUsername` (case-insensitive, `@` ignored) so the flow ends with `error=account_mismatch` and writes nothing when the user logs in to a different account.
- `forceReauth: true` makes Instagram Login show its login page even when another Instagram account is signed in on the device; other platforms ignore it.
- `scopes` requests only some permission areas (`posting`, `analytics`, `comments`, `messaging`, `ads`) instead of the platform's full set.
- `oauthAppId` connects through one of your own OAuth apps (see below), so the consent screen shows your app.
- `loginMethod` picks Instagram Login (`instagram_login`, the default) or Facebook Login (`facebook_login`).
- `welcome: true` sends the user to a Zernio-hosted welcome screen first; `brandName` (1 to 60 characters), `primaryColor` (`#RRGGBB`) and `logoUrl` (HTTPS, square) style it and are rejected without `welcome`.

```ts
const { url } = await native.createConnection(
  {
    platform: "instagram",
    profileId,
    redirectUrl,
    reconnectAccountId: expired.ref.accountId,
    expectedUsername: "studio",
    forceReauth: true,
  },
  context,
);
```

`connectDiscord({ guildId, channelIds, profileId, redirectUrl? })` finishes a Discord connect with `POST /v1/connect/discord`, binding 1 to 25 channels of the server (numeric snowflake IDs) to a profile. ### Bring your own OAuth app

White-label connects use your own platform app. `listOAuthApps({ limit?, cursor? })`, `createOAuthApp({ platform, label, clientId, clientSecret, metaAppId?, metaAppSecret?, scopeAreas? })`, `getOAuthApp`, `updateOAuthApp`, `testOAuthApp` (checks the keys with the platform) and `deleteOAuthApp({ appId, confirm? })` wrap `/v1/connect/oauth-apps`. The secrets go to Zernio only; returned records carry `status`, `lastError`, `accountCount` and the `redirectUri` to register with the platform, never a secret. Facebook and Instagram apps also return `webhook` (`callbackUrl`, `verifyToken`, `object` and `fields`): set that callback URL and verify token on the app's webhook product and subscribe the listed fields so Meta delivers comments and messages to your app. Slack apps return `hasSlackSigningSecret` and `slackEvents` (`requestUrl`, `botEvents`); TikTok apps return `sharedWebhookUrl`. Deleting with `confirm: true` also disconnects the accounts connected through the app and returns `disconnectedAccounts`. `getWelcomeScreen()` and `saveWelcomeScreen({ showByDefault, brandName?, logoUrl?, theme? })` read and save the default welcome screen at `/v1/connect/welcome-screen`.

const bluesky = await native.connectBluesky(

### Manage profiles and accounts

Give each tenant its own profile so its accounts and queue stay separate:

- `createProfile({ name, description?, color?, timezone?, externalId? })` sends `POST /v1/profiles`. `timezone` is the IANA zone for posts that name none, and `externalId` stores your tenant ID.
- `updateProfile({ profileId, ...fields })` sends `PUT /v1/profiles/{id}`. `null` clears `description`, `timezone` or `externalId`.
- `deleteProfile({ profileId })` permanently deletes the profile.
- `moveAccount({ account, profileId })` moves a connected account to another profile.

`getAccountHealth({ account })` reads `GET /v1/accounts/{id}/health`: overall `status` (`healthy`, `warning` or `error`), `token.valid`, `token.expiresAt` and `token.needsRefresh`, `permissions.canPost`, `canFetchAnalytics` and `missingRequired`, plus `issues`, `recommendations` and the disconnect reason. Tokens themselves are never returned. `disconnectAccount({ account })` disconnects and removes the account from Zernio; it cannot be undone, so confirm with the account owner first.

### Account groups

`listAccountGroups()`, `createAccountGroup({ name, accounts, profileId? })`, `updateAccountGroup({ groupId, name?, accounts? })` and `deleteAccountGroup({ groupId })` manage Zernio's account groups (`/v1/account-groups`), named sets of accounts. Deleting a group leaves its accounts connected.

### Usage and activity logs

`usageStats({ reconcile? })` reads `GET /v1/usage-stats`: plan name, billing period, access, `limits`, `usage` and `spend`. `listLogs({ type?, status?, account?, action?, search?, from?, to?, days?, limit?, skip? })` reads Zernio's activity logs from `GET /v1/logs` (publishing, connections, webhooks, messaging and API requests, up to 90 days back) with each entry's type, action, status, error, path and time. Logged request and response bodies, IP addresses and user agents are dropped, because they can hold message content.

### List posts with filters

`posts.list` reads one account's synced external posts. `listPosts({ account?, source?, status?, dateFrom?, dateTo?, sortBy?, createdBy?, profileId?, includeHidden?, search?, tags?, limit?, cursor? })` reads `GET /v1/posts` with Zernio's filters: a `dateFrom`/`dateTo` window (`YYYY-MM-DD` or ISO 8601), `sortBy` (`scheduled-desc` by default, or `scheduled-asc`, `created-desc`, `created-asc`, `status`, `platform`), `createdBy` (a team member ID), up to 20 `tags` that must all match, and `includeHidden`. Results page with `nextCursor`. Zernio's cursor is unavailable with `source: "external"`, which pages by number, so there `nextCursor` is the next page number to pass back as `cursor`. Each post lists its destinations with status and platform post ID. Zernio rejects query parameters its list-posts reference does not list, so there is no changed-since filter; to sync only what changed, use `analyticsDelta` and its `nextCursor`.

## Drafts, approval and the queue

`submitPost` creates a post that does not publish straight away. It takes one `account`, the `content` and `options` that `posts.publish` takes, with the same checks, and a `submission`:

- `{ kind: "draft" }` saves a draft (`isDraft`).
- `{ kind: "approval", at, timeZone? }` sets `requiresApproval` with `scheduledFor`, so the post waits in `pending_approval` until someone approves it. The outcome is `accepted`.
- `{ kind: "queue", profileId, queueId? }` takes the profile's next free queue slot (`queuedFromProfile`, optionally a specific `queueId`) instead of a fixed time. Create queue slots in Zernio first.

`reviewPost({ delivery, decision })` approves (`approve` schedules it) or rejects (`reject` returns it to draft) a `pending_approval` post through `POST /v1/posts/{id}/review`. Approving after the scheduled time publishes within a couple of minutes.

```ts
const pending = await native.submitPost(
  { account, content: { text: "Launch day" }, submission: { kind: "approval", at } },
  context,
);

if (pending.delivery)
  await native.reviewPost({ delivery: pending.delivery, decision: "approve" }, context);
```

## Change, edit, retry and validate posts

- `reschedulePost({ delivery, text?, at?, timeZone? })` changes the text or time of a draft, scheduled, failed or cancelled post with `PUT /v1/posts/{id}`. It is the `posts.update` path for posts that have not published; the new time must be in the future.
- `updatePost({ post, text })` edits a published post's text with `POST /v1/posts/{id}/edit` on X, Facebook, LinkedIn, YouTube, Reddit, Discord, Telegram, Pinterest and Google Business Profile. X edits need X Premium and only work within an hour of posting, and X assigns a new post ID, so store the returned reference.
- `updateYouTubeMetadata({ post, metadata })` changes a YouTube video's `title` (up to 100 characters), `description`, `tags` (500 characters combined), `categoryId`, `privacyStatus`, `thumbnailUrl`, `madeForKids`, `containsSyntheticMedia` or `playlistId` without a new upload, through `update-metadata` in direct video mode, so it also works on videos published outside Zernio.
- `retryPost({ delivery })` retries a failed post at once with `POST /v1/posts/{id}/retry` and returns the new outcome. Only a `failed` post can be retried.
- `validatePost({ account, content, options? })` sends the target to Zernio's validator, `POST /v1/tools/validate/post`, without creating anything, with the same text, platform options and `threadItems` that publishing sends, and returns `valid`, Zernio's `errors` and `warnings`, and the adapter's own `localIssues`. Each error keeps its `platform` and the explanation in `error`; each warning keeps `platform` and `warning`. Media must be public HTTPS URLs.
- `validatePosts({ content, targets })` validates several destinations in one call, each with the platform options and `threadItems` that publishing sends. `content` is the shared `content` and `mediaItems`; a target's own `content` text becomes that destination's `platforms[].customContent` and its own media becomes `customMedia`, which replace the shared values for that destination only. Publishing does not need these overrides, because the adapter creates one Zernio post per target from that target's own content.

Each of these reads the post first and refuses one whose single destination is a different account.

## TikTok creator info and live posts

TikTok requires apps to show the creator's privacy options before posting. `creatorInfo({ account, mediaType? })` reads `GET /v1/accounts/{id}/tiktok/creator-info` and returns the creator's `nickname`, `isVerified` and `canPostMore`, the `privacyLevels` to offer, the allowed `commercialContentTypes` and `maxVideoDurationSec`. Offer only those privacy levels in `options.privacy`.

`listPlatformPosts({ account })` reads the 25 most recent posts live from the platform through `GET /v1/accounts/{id}/posts`, including posts made outside Zernio, with their ID, text, permalink and counters. `posts.list` reads Zernio's synced copy instead.

Uploaded Zernio media refs expire locally after seven days. This SDK reuse limit is not a claim about the provider's public URL lifetime. Caller-owned HTTPS URLs do not receive this upload expiry. Configure `MemoryManagedMediaStore` or a persistent `ManagedMediaStore` from the backend subpath when references must survive adapter reconstruction.

## Raw requests

`zernioNative(options).request(input, context)` sends one request to a Zernio endpoint the SDK does not wrap, with the API key as a bearer token. It does not add the `Idempotency-Key` header that post creation uses.

The only host is `api` (`https://zernio.com/api`). Paths include the version, such as `/v1/accounts`.

```ts
// `native` is zernioNative(options); `context` is an AdapterOperationContext.
const response = await native.request({ method: "GET", path: "/v1/accounts" }, context);

if (response.responseType === "json") console.log(response.status, response.body);
```

`path` is relative to the base URL and starts with `/`; put parameters in `query`. Before any request, the adapter rejects absolute URLs, `//` paths, `..` segments, encoded separators, and `?` or `#` in the path. It also rejects credential and framing headers such as `Authorization`, `Cookie` and `Content-Type`. It does not follow redirects. A body has a `kind` of `json`, `text`, `bytes`, `form` or `urlencoded`, and its kind sets `Content-Type`; `text` and `bytes` also take a `contentType`. Set `responseType` to `"text"` or `"bytes"` for a body that is not JSON. Response bodies are capped at 2 MiB, and `maxResponseBytes` raises the cap to at most 16 MiB. The result has `status`, `responseType`, `body` and lowercase `headers`. Name extra headers in `responseHeaders`; `set-cookie` is never returned. A non-2xx response rejects with a `SocialError`.

The API key reaches the whole workspace, and the SDK cannot tell which accounts a raw path touches, so check the tenant's grants yourself before the call. A raw request makes one attempt. It adds no idempotency key and records no outcome, so you reconcile the writes you send. A write rejects with `ambiguous_outcome` when it fails without a definitive answer: a timeout, a cancellation after dispatch, a 5xx, or a 2xx body that cannot be decoded. Prefer a typed method when one exists.

## Limits and requirements

### Not supported

- Reddit: Zernio lists Reddit as temporarily unavailable because Reddit has blocked third-party apps from its API; see [Reddit](#reddit).
- A combined internal and external post feed: `posts.list` reads synced platform posts only (`source=external`).
- Publishing to WhatsApp: WhatsApp accounts are listed but not published to, because Zernio's WhatsApp surface is messaging.
- Headless selection steps: choosing a Facebook Page (`select-page`), a LinkedIn organization, a Pinterest board or a Google Business location carries the temporary OAuth token from Zernio's redirect, so these steps are not wrapped.
