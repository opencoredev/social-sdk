---
title: Post for Me
description: Configure Post for Me with server credentials, account-scoped publishing, feed analytics, and shared-secret webhooks.
---

Post for Me is an optional managed backend with its own connected-account records and lifecycle semantics.

```ts
import { createSocial } from "@opencoredev/social-sdk";
import { postForMe } from "@opencoredev/social-sdk/cloud/post-for-me";

const social = createSocial({ backend: postForMe({ apiKey: process.env.POST_FOR_ME_API_KEY! }) });
const accounts = await social.accounts.list({
  backend: "default",
  authorization: { tenantId: "tenant-from-session" },
});
```

The adapter supports account listing, publishing, post reads and status, media upload, feed-based post analytics, and verified webhooks. Comments and normalized messaging are unavailable in this adapter. Verify the `Post-For-Me-Webhook-Secret` header with your endpoint secret; this shared-secret check authenticates the header and does not authenticate the body. Resolve accounts to tenants, quarantine unknown mappings, and process accepted events durably. See [events](/events) and [capabilities](/reference/capabilities).

The examples below use this `social` client and pass `authorization` as the last argument of every call. Full, type-checked versions are in `examples/snippets/backend-post-for-me.ts`.

## Publish an image

Pass the file as a `Blob` with its MIME type and filename; the adapter uploads it to Post for Me before it creates the post. The adapter rejects `altText`, because Post for Me has no field for it.

```ts
const result = await social.posts.publish(
  {
    targets: [
      { account: xAccount, options: { replySettings: "following" } },
      { account: instagramAccount, options: { shareToFeed: true } },
    ],
    content: {
      text: "The new dashboard is live.",
      media: [
        {
          kind: "image",
          source: { kind: "blob", blob: image, fingerprint: "dashboard-launch-v1" },
          mimeType: "image/png",
          filename: "dashboard.png",
        },
      ],
    },
    idempotencyKey: "dashboard-launch-v1",
  },
  { authorization: { tenantId: "tenant-from-session" } },
);
```

Type each account as `ConnectedAccountRef<"x">` and so on so TypeScript checks the options. For TikTok, the adapter accepts only `SELF_ONLY` and `PUBLIC_TO_EVERYONE` privacy.

## Schedule and check a delivery

Set `schedule.at` and store the outcome's `delivery` reference. Later, read it with `getDelivery` and handle every state instead of treating the result as a boolean.

```ts
const result = await social.posts.publish(
  { targets: [{ account }], content: { text: "Maintenance window tonight." }, schedule: { at } },
  { authorization },
);
const delivery = result.outcomes[0]?.delivery; // store with the publication

// Later, for example from a job:
const outcome = await social.posts.getDelivery(delivery, { authorization });
const action = nextStep(outcome);

function nextStep(outcome: DeliveryOutcome): string {
  switch (outcome.state) {
    case "published":
      return `published ${outcome.url ?? outcome.post.postId}`;
    case "scheduled":
      return `scheduled as ${outcome.job.jobId}; check again after the scheduled time`;
    case "accepted":
    case "processing":
      return "Post for Me is still working; check again later";
    case "failed":
      return `failed with ${outcome.code}`;
    case "cancelled":
      return "cancelled";
    case "not-submitted":
      return `not submitted: ${outcome.reason}`;
    case "unknown":
      return "state is unclear; reconcile before retrying";
  }
}
```

A `processed` post without a result for this account reads as `unknown`, so reconcile it rather than assuming success.

## Cancel and delete a scheduled post

Cancelling works on a record with one destination whose time is still in the future. Post for Me keeps the record as a draft and the result reports `backendRecord: "retained"`; delete the draft with `deleteBackendRecord` if you do not need it.

```ts
if (outcome.state === "scheduled") {
  const cancellation = await social.posts.cancelScheduled(outcome.job, { authorization });

  if (cancellation.backendRecord === "retained") {
    const draft: BackendPostRef = {
      kind: "backend-post",
      version: 1,
      backend: outcome.job.backend,
      platform: outcome.job.platform,
      accountId: outcome.job.accountId,
      recordId: outcome.job.jobId,
    };
    await social.posts.deleteBackendRecord(draft, { authorization });
  }
}
```

`deleteBackendRecord` only deletes drafts. Neither call removes a post that already published, and this adapter has no `removeFromPlatform`.

## Read analytics from the feed

Post metrics come from the account feed, so they report `freshness: "unknown"`. List the feed, build a post reference from each `platform_post_id`, and read its metrics.

```ts
const feed = await social.posts.list(account, { limit: 10, authorization });

for (const item of feed.items) {
  const postId = item["platform_post_id"];
  if (typeof postId !== "string") continue;

  const post = platformPostRef({
    backend: account.backend,
    platform: account.platform,
    accountId: account.accountId,
    postId,
  });
  const metrics = await social.analytics.getPostMetrics(post, { authorization });
}
```

The `post` from a `published` outcome works the same way.

## Receive webhooks

Read the raw bytes, check the shared-secret header, then decode and accept the event. Only the verify call sits inside the `try`, so a decoding or inbox failure is not reported as an authentication error.

```ts
import { SocialError } from "@opencoredev/social-sdk";
import {
  acceptWebhook,
  decodeWebhook,
  verifyPostForMeWebhook,
} from "@opencoredev/social-sdk/server";

export async function POST(request: Request): Promise<Response> {
  const body = new Uint8Array(await request.arrayBuffer());

  try {
    await verifyPostForMeWebhook({
      secret: process.env.POST_FOR_ME_WEBHOOK_SECRET!,
      headers: request.headers,
      body,
    });
  } catch (error) {
    if (error instanceof SocialError && error.code === "unauthorized")
      return new Response("unauthorized", { status: 401 });
    throw error;
  }

  const event = await decodeWebhook({ provider: "post-for-me", backend: "default", body });
  const result = await acceptWebhook({ event, endpointId, inbox, resolveTenants });
  return new Response(result.state, { status: 202 });
}
```

The header check does not authenticate the body, so do not act on its contents. In the worker, look up your stored delivery by `event.backendRecordId` and read the current state from Post for Me:

```ts
if (event.type === "publication.updated" && event.backendRecordId !== undefined) {
  const delivery = await findDelivery(event.backendRecordId);
  if (delivery) await social.posts.getDelivery(delivery, { authorization });
}
```

## Connect accounts

The native adapter starts a hosted Post for Me connection flow. `permissions` takes `posts`, `feeds`, or both. Native calls skip the client's authorization and concurrency checks, so run them only after your own checks.

```ts
const context: AdapterOperationContext = {
  backendInstance: "default",
  correlationId: crypto.randomUUID(),
  retryBudget: { maxAttempts: 1, maxElapsedMs: 30_000 },
  authorization: { tenantId: "tenant-from-session" },
};

const native = social.native("default", { acknowledgeUnsafe: true });
const { url } = await native.createConnection(
  {
    platform: "instagram",
    externalId: "customer-42",
    permissions: ["posts", "feeds"],
    redirectUrl,
  },
  context,
);
```
