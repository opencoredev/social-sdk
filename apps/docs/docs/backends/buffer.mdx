[Buffer](https://buffer.com) is an optional managed backend. Buffer holds the social channels connected to a Buffer organization and publishes or queues posts through its GraphQL API at `https://api.buffer.com`. Create a personal API key under Settings → API, or let other people approve your Buffer OAuth app. The key or access token stays on the server and is sent as `Authorization: Bearer`.

For Buffer's API access rules, scheduling modes, and rate limits per plan in one place, read the <a href="/guides/buffer-api">Buffer API guide</a>.

```ts
import {
  createSocial,
  connectedAccountRef,
  type ConnectedAccountRef,
  type DeliveryOutcome,
  type Platform,
} from "@opencoredev/social-sdk";
import { buffer } from "@opencoredev/social-sdk/cloud/buffer";

// Get tenantId from your authenticated server session and enforce account grants.
const authorization = { tenantId: "tenant-from-session" };
const social = createSocial({
  backend: buffer({
    apiKey: process.env.BUFFER_API_KEY!,
  }),
});
const accounts = await social.accounts.list({ backend: "default", authorization });

function selectAccount<P extends Platform>(platform: P): ConnectedAccountRef<P> {
  const match = accounts.items.find((item) => item.ref.platform === platform);
  if (!match) throw new Error(`Connect a ${platform} channel first.`);
  return connectedAccountRef({
    backend: match.ref.backend,
    platform,
    accountId: match.ref.accountId,
  });
}

const account = selectAccount("x");
const youtubeAccount = selectAccount("youtube");
const at = new Date(Date.now() + 7 * 86_400_000).toISOString();
```

A Buffer API key acts for the Buffer account that created it and can read every organization on that account. Pass `organizationId` when you want the adapter to query only one organization. Connected channels are Buffer records; your application must map them to tenants before any write.

The adapter lists channels, publishes now, at `schedule.at`, or into the channel's queue, saves drafts and approval requests, reads posts and delivery status, edits and reorders unsent posts, cancels a future scheduled post, deletes draft, approval, or failed Buffer records, reads post metrics after a post is sent, and reads a channel's aggregated metrics. It does not upload files, verify webhooks, comment, message, or remove a post from the destination network. See [capabilities](/reference/capabilities). Related server helpers are in `examples/snippets/backend-buffer.ts`.

## Publish now or schedule

Omit `schedule` to send `mode: shareNow`. Set a future `schedule.at` to send `mode: customScheduled` with that UTC timestamp. Both paths use `schedulingType: automatic` unless you choose reminder publishing below. With neither `schedule.at` nor `shareMode`, the post shares now. To use the channel's posting schedule instead, omit `schedule` and set the `shareMode` option: `addToQueue` takes the next free slot after the posts already queued, and `shareNext` puts the post at the front of the queue. A queued post returns `scheduled`. `shareMode` and `schedule.at` cannot be combined.

```ts
const result = await social.posts.publish(
  {
    targets: [{ account }],
    content: { text: "Office hours start at 10:00." },
    schedule: { at, timeZone: "Europe/Berlin" },
  },
  { authorization },
);
```

These options work on every Buffer target:

| Option                           | Buffer field                       | What it does                                                                                                                                                                                                            |
| -------------------------------- | ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `shareMode`                      | `mode`                             | `addToQueue` or `shareNext`, as above.                                                                                                                                                                                  |
| `schedulingType: "notification"` | `schedulingType`                   | Reminder publishing: at the due time Buffer reminds someone to publish the post by hand, instead of its workers sending it. The default is `automatic`.                                                                 |
| `saveToDraft: true`              | `saveToDraft`                      | Save the post as a Buffer draft. Buffer does not check posting limits for a draft and publishes nothing until someone schedules it. The outcome is `accepted`.                                                          |
| `needsApproval: true`            | `needsApproval`                    | Submit the post for approval, on a channel whose posting policy requires it. Such a post is always a draft, so `saveToDraft: false` with it is rejected. The outcome is `accepted` with Buffer status `needs_approval`. |
| `tagIds`                         | `tagIds`                           | Buffer tag IDs to label the post with. Tags are a beta Buffer feature.                                                                                                                                                  |
| `ideaId`                         | `ideaId`                           | Link the post to a Buffer idea, such as one from `native.createIdea`.                                                                                                                                                   |
| `aiAssisted: true`               | `aiAssisted`                       | Record that the post was written with the help of AI. This is Buffer's own provenance flag, separate from the network AI labels below.                                                                                  |
| `draftId`                        | `draftId`                          | Link the post to the Buffer draft it was generated from.                                                                                                                                                                |
| `animatedThumbnails`             | image `metadata.animatedThumbnail` | A list of `{ imageIndex, url }`: a public HTTPS animated preview, such as a GIF, for the image at that position in `media`. See [Media](#media-is-a-public-https-url).                                                  |

A reminder post never reports `published`: when Buffer marks it `sent`, the outcome is `unknown`, because Buffer sent the reminder and cannot tell whether the person posted it. Check the network instead.

`timeZone` is application metadata only; Buffer's `dueAt` is UTC. Store `result.outcomes[0]?.delivery` and read it later with `getDelivery`. Buffer statuses map as `scheduled` → `scheduled`, `sending` → `processing`, `draft` or `needs_approval` → `accepted`, `sent` → `published`, and `error` → `failed`. A `failed` outcome's message carries Buffer's failure reason from the post's `error.message`, plus its help-center `supportUrl` when Buffer has one. A `published` outcome uses the Buffer post ID. Buffer's public schema does not return the destination network's post ID.

`posts.get`, `posts.list`, and `native.listPosts` return each post's `id`, `text`, `status`, `dueAt`, `sentAt`, `createdAt`, `shareMode`, and `url`, plus what Buffer stores with it: `assets` (each `{ type, url, thumbnailUrl, mimeType, altText?, animatedThumbnail? }`), workspace `tags` (`{ id, name, color }`), the `author` (`{ id, name? }`; the adapter does not read the author's email), the network `postType` (such as `reel`), `ideaId`, `via` (`buffer`, `api`, or `network`), `notificationStatus` for reminder posts (`notified` or `markedAsPublished`), and `allowedActions`, the actions your credentials may take on the post, such as `updatePost` or `requestPostApproval`. A failed post carries `error` with Buffer's `message`, `supportUrl`, and `rawError`, the network's original error, which Buffer marks as internal and may leave empty.

## Media is a public HTTPS URL

Buffer has no upload mutation. Host the file yourself and pass a stable public HTTPS URL. Buffer fetches the file when the post publishes, which can be hours or days later, so expiring or signed URLs fail after create. This adapter maps image and video assets, including an ordered multi-image carousel when the destination supports it, and document assets on LinkedIn: a document needs an HTTPS `thumbnail` and a `caption` or `filename` for its title (see below).

Buffer rejects custom video thumbnail images. To pick the cover frame of a single video on Instagram, TikTok, or Pinterest, set the `thumbnailOffset` option in milliseconds; the adapter sends it as the video's `metadata.thumbnailOffset`. To tag Instagram accounts on an image, set `userTags` to a list of `{ username, x, y, mediaIndex? }`: `username` with or without the `@` (sent as Buffer's `handle`), `x` and `y` as fractions of the image width and height from 0 to 1, and `mediaIndex` the image's position in `media` (default 0). Buffer's own names, `handle` without the `@` and `imageIndex`, also work; use one name of each pair per tag. Buffer's image metadata requires alt text, so set `altText` on each tagged image; an empty `altText` is sent as `""` with the tags.

An image's `thumbnail`, at a public HTTPS URL, is sent as the image asset's `thumbnailUrl`, the static preview Buffer shows. For an animated image such as a GIF, the `animatedThumbnails` option sets `metadata.animatedThumbnail`, the animated preview: a list of `{ imageIndex, url }`, one per image. Buffer's image metadata requires `altText`, so the adapter sends an empty `altText` when the image has none. A video `thumbnail` is rejected (`media.thumbnail_unsupported`) because Buffer rejects video assets that set `thumbnailUrl`; use `thumbnailOffset` instead.

```ts
const scheduled = await social.posts.publish(
  {
    targets: [
      {
        account: youtubeAccount,
        options: {
          title: "Release walkthrough",
          categoryId: "22",
          visibility: "unlisted",
          madeForKids: false,
        },
      },
    ],
    content: {
      text: "A two-minute tour of the new release.",
      media: [
        {
          kind: "video",
          mimeType: "video/mp4",
          source: { kind: "https-url", url: "https://cdn.example/release-walkthrough.mp4" },
        },
      ],
    },
  },
  { authorization },
);
```

YouTube requires `title`, `categoryId`, `visibility`, and `madeForKids`; these are sent as Buffer `metadata.youtube`. Instagram requires an explicit boolean `shareToFeed`, sent as `metadata.instagram.shouldShareToFeed` with `type: post`, or the `postType` you choose. Without `postType`, the post goes out as a feed post. X reply settings have no Buffer Twitter field.

A thread publishes in order, each reply answering the previous one. Buffer takes the whole thread in the service's metadata, such as `metadata.twitter.thread` for X, so the adapter sends the post's own text and media as the first item; the replies carry text only. A link card needs no text of its own and cannot be combined with attachments, and Buffer is replacing the older link asset with `linkAttachment` on December 15, 2026. On X, a `retweet` without `comment` reposts, and needs no text of its own; Buffer labels AI content only on original posts, so `aiGenerated` with `retweet` is rejected. An Instagram or Facebook reel is a single video. Annotations mark mentions and links in the text by position; build them from the entity IDs the network gives you.

Substack channels are listed and publish as `substack`, Buffer's service for Substack Notes. A Note takes text up to 10,000 characters and one image, one video, or a `content.link` link card in `metadata.substack.linkAttachment`; preparation rejects more attachments (`substack.media_count`) and longer text (`substack.text_too_long`). Buffer reports Substack's `freeSubscriptions` and `paidSubscriptions` per Note as post metrics.

For Google Business, a `whats_new` update can carry a call to action (`book`, `call`, `learn_more`, `none`, `order`, `shop`, or `signup`; all but `none` and `call` need an HTTPS `url`). An `event` needs a title, ISO start and end dates, and `isFullDayEvent`; an `offer` needs a title and dates and can carry a coupon `code`, `terms`, and an HTTPS `link`. Buffer marks this Google metadata as deprecated while it designs separate update, event, and offer types.

```ts
await social.posts.publish(
  {
    targets: [
      {
        account,
        options: {
          shareMode: "addToQueue",
          thread: [{ text: "2/ What changed" }, { text: "3/ Try it today" }],
        },
      },
    ],
    content: { text: "1/ The new scheduler is live." },
  },
  { authorization },
);
```

## Cancel or delete a Buffer record

`posts.cancelScheduled` deletes a still-future `scheduled` post. `posts.deleteBackendRecord` deletes a `draft`, `needs_approval`, or `error` record. A sent or in-flight post is rejected. Buffer's `deletePost` removes the Buffer record only (see [Not supported](#not-supported)).

## Connect other Buffer accounts with OAuth

A personal API key is enough for your own automations. For an app that other people sign in to, register an OAuth client under Settings → API. Buffer requires the authorization-code flow with PKCE for every client. Confidential clients also send `client_secret`. Request `offline_access` if you need a refresh token. Refresh tokens are single-use: store the replacement and discard the old one.

```ts
import {
  bufferAuthorizationUrl,
  createBufferPkce,
  exchangeBufferCode,
  refreshBufferToken,
} from "@opencoredev/social-sdk/cloud/buffer";

interface OAuthSession {
  bufferState?: string | undefined;
  bufferVerifier?: string | undefined;
}

export function startOAuth(session: OAuthSession): Response {
  const pkce = createBufferPkce();
  const state = crypto.randomUUID();
  session.bufferState = state;
  session.bufferVerifier = pkce.codeVerifier;

  return Response.redirect(
    bufferAuthorizationUrl({
      clientId: process.env.BUFFER_CLIENT_ID!,
      redirectUri: "https://app.example/buffer/callback",
      state,
      codeChallenge: pkce.codeChallenge,
    }),
  );
}

export async function finishOAuth(session: OAuthSession, url: URL) {
  if (url.searchParams.get("state") !== session.bufferState) throw new Error("Invalid state.");
  const code = url.searchParams.get("code");
  const verifier = session.bufferVerifier;
  if (!code || !verifier) throw new Error("Missing authorization code or PKCE verifier.");

  const tokens = await exchangeBufferCode({
    clientId: process.env.BUFFER_CLIENT_ID!,
    clientSecret: process.env.BUFFER_CLIENT_SECRET,
    code,
    redirectUri: "https://app.example/buffer/callback",
    codeVerifier: verifier,
  });

  return {
    backend: buffer({ apiKey: tokens.accessToken }),
    tokens,
  };
}

export async function refresh(tokens: { refreshToken: string }) {
  const refreshed = await refreshBufferToken({
    clientId: process.env.BUFFER_CLIENT_ID!,
    clientSecret: process.env.BUFFER_CLIENT_SECRET,
    refreshToken: tokens.refreshToken,
  });

  // Persist `refreshed.refreshToken` before replacing the old token.
  return refreshed;
}
```

Default scopes are `posts:read`, `posts:write`, `account:read`, and `offline_access`. Pass `scopes` to request others from `bufferScopeNames`, the scopes Buffer documents: `ideas:read` and `ideas:write` (ideas; `native.createIdea` needs `ideas:write`), `account:write` (account settings), `snippets:read` and `snippets:write` (snippets), and `notes:read` and `notes:write` (collaboration notes on posts and drafts). Ideas, snippets, and account writes are not used by the default scopes; the adapter needs `ideas:write` only for `native.createIdea`.

## Errors, rate limits, and metrics

GraphQL usually returns HTTP 200. Non-recoverable failures arrive in `errors` with codes such as `UNAUTHORIZED`, `FORBIDDEN`, `NOT_FOUND`, `UNEXPECTED`, and `RATE_LIMIT_EXCEEDED`. Recoverable create/delete failures arrive as `MutationError.message` on HTTP 200 and become `invalid_input`. HTTP 429 includes `Retry-After`. Limits are per API key or app client and depend on the Buffer plan; the documented windows are 15 minutes, 24 hours, and 30 days. Query complexity, depth, alias, directive, and token limits also apply.

`analytics.getPostMetrics` reads `Post.metrics` after status `sent`. Metrics need a personal API key: they require Buffer's `insightsRead` scope, which an OAuth app client cannot request, so app tokens cannot read them. Values refresh about once a day. Buffer reports each metric as a `count` or a `percentage` (such as `engagementRate`, from 0 to 100), and the adapter keeps only those two units.

`analytics.getReport` reads `aggregatedPostMetrics` for one channel. Pass `from` and `to` dates covering at most 365 days with both ends counted (Buffer includes the whole `to` day), and the metric types you want, such as `postCount`, `reactions`, `comments`, `impressions`, or `engagementRate`. The report has one row keyed by `channelId` with the requested metrics Buffer returned; Buffer always returns `postCount`, `reactions`, and `comments`, and other types only where the network reports them. It takes no dimensions, and needs a personal API key like post metrics.

```ts
const report = await social.analytics.getReport(
  account,
  { from: "2026-07-01", to: "2026-09-30", metrics: ["postCount", "reactions", "engagementRate"] },
  { authorization },
);
```

Pinterest, Mastodon, and Google Business Profile channels are listed and publish as `pinterest`, `mastodon`, and `google-business`. Pinterest needs `boardId` and accepts `title` and `link`. WhatsApp channels are listed but not published to (see [Not supported](#not-supported)). Substack channels publish as `substack` (see [Platform options](#platform-options)). Start Page is outside this adapter, and its channels are left out unless you set `unknownPlatforms: "include"`. Edits and deletions of ideas, tags, and templates are outside this adapter, as is creating tags or templates: beyond the `tagIds` and `ideaId` options, it creates and lists ideas only through the idea methods under [Native methods](#native-methods). LinkedIn document assets publish from an HTTPS URL when you also supply an HTTPS `thumbnail` and a `caption` or `filename` for the title. Live publication, plan eligibility, and channel reconnects remain Buffer-side constraints.

## Limits and requirements

### Not supported

- Webhooks: Buffer offers no public webhooks, so poll `getDelivery` for status.
- Comments and messages: Buffer's API exposes no comments or inbox to this adapter.
- Post templates, collaboration notes, snippets, and content items: these are Buffer beta and experimental Create-space features with no publishing role here. Request the `snippets:*` or `notes:*` scopes and call Buffer's API directly if you need them.
- Instagram audio on posts: see `searchInstagramAudio` above.
- Uploads: host media yourself, as described above.
- Removing a published post: Buffer's `deletePost` removes the Buffer record; it is not advertised as native network removal.
- Publishing to WhatsApp: WhatsApp channels are listed, but this adapter does not publish to them.

Run the setup on your server with your own assets and connected channels. In a multi-tenant app, configure an [authorization policy](/concepts/tenant-authorization) backed by your account grants; listing channels is not a tenant grant.
