A managed backend is optional: instead of calling a social platform's API with credentials you control, the SDK calls Zernio, Post for Me, PostFast, Postiz, or Buffer using your own provider account. Managed providers own the platform apps and account connections; with self-hosted Postiz, you configure your own instance and platform apps; your application keeps tenant authorization and outcome handling.

Direct integrations remain the other route: your platform app, your tokens, your review processes, no provider charges. Each [platform page](/platforms) documents that route. Nothing routes through a maintainer-operated service in either mode, and an application can use any of the providers, several, or none.

For native platform APIs, unified social media APIs, and libraries compared side by side, read the <a href="/guides/social-media-apis">social media APIs guide</a>.

Moving off Ayrshare? The <a href="/guides/ayrshare-alternatives">Ayrshare alternatives guide</a> maps its profiles and post calls to the SDK.

## Postiz, Buffer, or the platform APIs?

For a solo founder adding posting to an app, the choice comes down to who holds the platform apps and account connections, and which limits you accept:

- **Postiz** is open source (AGPL-3.0). Use Postiz Cloud, or host it yourself and register your own platform apps. Its public API allows 90 create-post requests per hour on a self-hosted instance and 100 on Postiz Cloud. That limit is one value for the whole instance, not set by plan, and self-hosters can change it with `API_LIMIT`; several posts can go in one request ([Postiz API overview](https://docs.postiz.com/public-api/introduction), read November 16, 2026). On Postiz Cloud, the API key needs a plan that includes the public API.
- **Buffer** fits when you or your users already schedule in Buffer. Its GraphQL API is included on every Buffer plan, including Free, and it can add posts to each channel's queue. API-key limits depend on the plan and are shared by all of your keys: Free allows 150 requests per 15 minutes, 600 per 24 hours, and 1,000 per channel per 30 days, up to 3,000. An OAuth app acting for other Buffer users has separate limits that grow with the number of users who authorize it ([Buffer API limits](https://developers.buffer.com/guides/api-limits.md), read November 16, 2026). Media must already be at a public HTTPS URL, and there are no status webhooks, so poll status within those limits.
- **The platform APIs directly** add no provider bill, but most networks need a developer app and a review before you can post for other people: Meta App Review for Threads and Instagram users outside your app's roles, LinkedIn's Community Management API for Page posts, and TikTok's audit before posts can be public. X bills API use from prepaid credits. Bluesky needs no developer app; you log in as the account with an app password or OAuth. The [platform pages](/platforms) list each network's requirements.

With Social SDK, all three use the same `social.posts.publish` call and return one outcome per destination. What changes is the backend you register in `createSocial`, the account references, which come from each provider, how media is passed (Buffer takes only public HTTPS URLs, while PostFast takes file bytes or a PostFast media reference), which formats each provider accepts, and provider-specific options such as PostFast's required `schedule.at`. You can also register several backends in one client, as shown [below](#use-two-providers-together). The Postiz and Buffer adapters are on `main` and not yet in the npm release (0.5.0); the direct adapters and the Zernio, Post for Me and PostFast adapters are. The <a href="/guides/buffer-api">Buffer API guide</a> covers Buffer's access rules in more depth.

Zernio's [platform comparison](https://docs.zernio.com/platforms/compare), checked November 4, 2026, lists Reddit as temporarily unavailable: Zernio cannot post to Reddit, read Reddit messages, or sync Reddit analytics because Reddit has blocked third-party apps from its API. The SDK's Zernio Reddit methods remain, but Zernio refuses those requests for now. See [Zernio](/backends/zernio).

The same comparison marks Google Business Profile, Telegram and Discord as having no post metrics, so expect none from `getPostMetrics` there. Google deprecated per-post analytics for Business Profiles. Zernio's separate Performance API reports location-level impressions, clicks, calls, directions and bookings, which are location metrics rather than post metrics; `zernioNative.googleBusinessPerformance` reads them as daily series, and `zernioNative.googleBusinessSearchKeywords` reads the search terms that showed a location. Snapchat is in closed beta at Zernio. Account follower counts can be missing without Zernio's Analytics add-on.

A dash means unimplemented in this SDK, not absent from the vendor API. This manually maintained comparison describes the normalized SDK surface alongside the generated [capability matrix](/reference/capabilities); they do not certify a provider account, plan tier, platform permission, or a live request.

You pay the selected provider directly and remain responsible for its plan, platform permissions, add-ons, and connected-account terms.

Publishing formats depend on the platform. YouTube requires video; Instagram, TikTok, and Pinterest require media; Zernio Snapchat takes video only. PostFast Bluesky takes text, images, or one MP4 video of at most 100 MB, never images and video together. Zernio, Post for Me, PostFast and Buffer publish LinkedIn documents; Postiz does not. The listed generic formats do not imply stories, reels, custom thumbnails, or every vendor option. Zernio, Post for Me, Postiz, and Buffer publish now or on a schedule; PostFast schedules only. Cancel deletes the scheduled record for Zernio, PostFast, Postiz, and Buffer; Post for Me retains a draft. Buffer media must already be a public HTTPS URL. Feed scope and metric availability vary by platform and connection permissions.

## What managed routes share

- The provider API key stays on your server and is passed to the adapter. Connected accounts are provider records that your application must map to tenants before any operation.
- Provider acceptance is not platform publication. Preserve the provider record, inspect every destination result, and reconcile pending or uncertain deliveries.
- Zernio verifies HMAC over raw bytes. Post for Me checks an endpoint-secret header, which does not authenticate the body, so workers must read current provider state. PostFast and Buffer have no public webhook verifier, and the SDK does not accept unsigned Postiz callbacks; poll those routes. See [events](/events).
- Social SDK does not pool keys, resell provider usage, or transfer authorizations between providers. PostFast and Postiz sponsor the project; that does not change how any adapter behaves.

## Use two providers together

Register each adapter under its own name in `backends`. Accounts carry the name as `backend`, so one publish call can target accounts from both providers and returns one outcome per target. The full example is in `examples/snippets/backend-mixed.ts`.

```ts
import { createSocial } from "@opencoredev/social-sdk";
import { postfast } from "@opencoredev/social-sdk/cloud/postfast";
import { zernio } from "@opencoredev/social-sdk/cloud/zernio";

const social = createSocial({
  backends: {
    zernio: zernio({ apiKey: process.env.ZERNIO_API_KEY! }),
    postfast: postfast({ apiKey: process.env.POSTFAST_API_KEY! }),
  },
});

const authorization = { tenantId: "tenant-from-session" };
const zernioAccounts = await social.accounts.list({ backend: "zernio", authorization });
const postfastAccounts = await social.accounts.list({ backend: "postfast", authorization });

const zernioX = zernioAccounts.items.find((item) => item.ref.platform === "x")?.ref;
const postfastLinkedIn = postfastAccounts.items.find(
  (item) => item.ref.platform === "linkedin",
)?.ref;
if (!zernioX || !postfastLinkedIn) throw new Error("Connect both destination accounts first.");
const at = new Date(Date.now() + 7 * 86_400_000).toISOString();

const result = await social.posts.publish(
  {
    targets: [{ account: zernioX }, { account: postfastLinkedIn }],
    content: { text: "Registration for the spring cohort is open." },
    schedule: { at },
  },
  { authorization },
);
```

PostFast only schedules, so a mixed post that includes a PostFast target needs a future `schedule.at` within one year. Load `authorization.tenantId` from the authenticated server session and enforce account grants with an [authorization policy](/concepts/tenant-authorization). Listing accounts alone is not a tenant grant.

:::warning
Moving application code from one backend to another does not move connected accounts, scheduled jobs, publication history, analytics history, or provider-native identifiers. Plan a provider migration as new authorization and data-mapping work.
:::
