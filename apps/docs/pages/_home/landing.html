What you get back

One outcome per target. Not a boolean. The actual state: "published", "processing", "accepted", "failed", "unknown", and more, with the reason when there is one.

Each target is checked before anything is sent. A text-only post aimed at Instagram fails local preparation, and no target is dispatched. 

import { createSocial } from "@opencoredev/social-sdk";

  const social = createSocial({ backend });

  const result = await social.posts.publish({
    content: { text: "we drew our landing page" },
    targets: accounts.map((account) => ({ account })),
  });

  for (const o of result.outcomes) {
    // "published" | "processing" | "failed" | ...
    console.log(o.account.platform, o.state);
  }

Everything it does.

Publishing

Explicit targets, explicit accounts, one outcome per destination. Retries that reuse an idempotency key with a durable store are deduplicated.

unknown means reconcile

Reads & analytics

Typed references to native content, plus platform analytics products where available. Missing metrics are left out, not reported as zero. Unsupported reads fail with unsupported_capability.

no made-up zeros

Comments & messages

Replies, reactions, conversations, and native platform operations, with capability declarations for normalized routes and explicit authorization for native access.

where platforms allow

Deterministic testing

A mock backend with deterministic scenarios, fixtures, and a fake clock, so CI never touches a live network.

runs offline
